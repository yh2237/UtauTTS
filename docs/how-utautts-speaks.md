# 音声合成の仕組み

UtauTTSは、UTAUボイスバンクの原音をつなぎ合わせて文章を読み上げる連結型音声合成システムです。

入力テキストに応じて最適な原音（「あ」「か」「a か」など）を選択し、音高（ピッチ）や音素長を調整して重ね合わせます。抑揚モデルがピッチの変化とモーラごとの音量を予測し、原音波形を用いて発声を生成します（※DiffSinger音源の場合は音源側の音響モデルが声を生成します）。

テキスト入力からWAV出力までの処理フローは以下の通りです。

1. **テキスト解析**: テキストを読みとモーラに分解する
2. **原音候補の抽出**: ボイスバンクから対応する原音候補を収集する
3. **配置時刻の決定**: `oto.ini`の原音設定に基づき、各原音の配置タイミングを決める
4. **抑揚・音量の予測**: 10ms単位のピッチ曲線とモーラごとの音量を算出する
5. **波形合成**: 原音の長さと高さを変換し、重ね合わせて単一の波形を生成する


## 1. テキスト解析（読み・モーラ分解）

日本語の音声合成では、文字数ではなく「モーラ（拍）」を基本単位として扱います（例: 「こんにちは」は5モーラ、「きゃ」は2文字で1モーラ）。

読みとモーラの算出と同時に、Open JTalkを用いて単語境界、品詞、アクセント句の長さ、アクセント核の位置などの言語情報を取得します。

中国語も同様のフローで処理します。ただし、単位にはモーラの代わりに音素（子音・母音など）を用い、アクセントの代わりに声調を使用します。英語は原音をつながず、参照音声に近いフレームを選んで合成します（[9. 英語の読み上げ](#9-英語の読み上げ)）。

## 2. 原音選択（ユニット選択）

UTAUボイスバンクには主に以下の収録形式があります。

| 形式 | 原音例 | 特徴・用途 |
| --- | --- | --- |
| **CV（単独音）** | か | 子音と母音を1セットで扱う |
| **VCV（連続音）** | a か | 前の母音から次の音への遷移（渡り）を含む |
| **CVVC** | あ + a k + か | 母音から次の子音へつなぐVC原音を間に挟む |

`oto.ini` の原音設定値は基本的にそのまま適用されます。ただしVCVにおいて、設定された先行発声が短いモーラ長に対して長すぎる場合や設定値に矛盾がある場合は、子音の遷移感を保持しつつ音声を適正長に縮小します。

文全体の区切りごとに音階や収録形式の異なる原音候補をリストアップし、**発音適合スコア（Target Cost）** と **接続スコア（Concatenation Cost）** に基づいて最適な組み合わせを選択します。

評価関数は以下の通りです。

$$S(U)=\sum_i L(u_i)+\sum_{i=2}^{N}J(u_{i-1},u_i)$$

- $U=(u_1,u_2,\ldots,u_N)$: 選択された原音系列（CVVCのVC原音とメイン原音の組みも1つの候補として処理）
- $L(u_i)$: 対象モーラに対する原音の適合度（指定の音階・音色・収録形式、代替候補へのフォールバック回数などを評価）
- $J(u_{i-1},u_i)$: 前後原音の接続のスムーズさ（境界付近の音量、スペクトル包絡、基本周波数 $F_0$ などを評価）

全体の合計スコアが最も高くなる経路を **Viterbiアルゴリズム** で探索します。

なお、同一の録音WAVファイル内で連続する原音を選択した場合は、接続の自然さを考慮して連続性ボーナス（6〜9点）が加算されます（時間間隔が500ms以下で9点、2000ms以上で6点へ直線的に減衰）。これにより、マルチモーラ音源等での渡り音の選択漏れを防ぎます。

候補選択は必要な音素文脈とボイスバンクの定義に基づいて絞り込まれるため、境界スコアのみの理由で異読や不適切な音素へ入れ替わることはありません。

### （参考）関連する音声合成方式

UtauTTSのユニット選択ロジックは、AppleのSiri（[Apple解説](https://machinelearning.apple.com/research/siri-voices) / [Interspeech 2017論文](https://www.isca-archive.org/interspeech_2017/capes17_interspeech.html)）で用いられる **Hybrid Unit Selection** と共通する概念を持っています。

Siriはニューラルネットワークで音響特徴の分布を予測し、Target cost と Concatenation cost を計算してViterbi探索で単位（Unit）を接続します。UtauTTSも同様のアプローチですが、数万〜数百万の単位（half-phone）を持つSiriに対し、一般のUTAUボイスバンクは各文脈に対する候補数が数個程度と限定的である点が異なります。


## 3. モーラ長の決定

標準の日本語抑揚モデル（`frame-intonation-tcn-v12`）はモーラ長の予測を行わないため、モーラ長はGUI指定の基準値と言語規則に基づき決定されます（例: 「ん」は0.9倍、「ー」は1.2倍、「っ」は1.0倍。GUIでの個別指定がある場合はそれを優先）。

モーラ $i$ の長さを $D_i$ とすると、基準時刻 $T_i$ は以下のように順次求まります。

$$T_1=0,\qquad T_{i+1}=T_i+D_i$$

また、句読点や記号に応じたポーズ（ポーズ長は読点＜疑問符・「…」＜文末の順で伸長）も独立した時間長として挿入されます。

## 4. 原音設定（oto.ini）の適用

原音WAVの使用範囲や子音区間の定義は `oto.ini` に記述されています。

| パラメータ | 概要 |
| --- | --- |
| **offset** | 原音の再生開始位置（WAV先頭からのミリ秒） |
| **consonant** | 固定範囲（音素長変更時に伸縮させず保持する子音区間） |
| **cutoff** | 除外範囲（WAV末尾からの除外長、または再生長指定） |
| **preutterance** | 先行発声（音素の発声タイミング基準点に対する先行時間） |
| **overlap** | オーバーラップ（前原音と交差・重ね合わせる範囲） |

モーラ $i$ の基準時刻を $T_i$、先行発声を $P_i$ とすると、原音の配置開始時刻 $B_i$ は以下の通りです。

$$B_i=T_i-P_i$$

子音（例: 「か」の /k/）は音素の発声開始（破裂・打音）が母音の立ち上がりより前に位置するため、先行発声分だけ配置時刻を前方にシフトして直前の音と重ね合わせます。

文頭で $B_1 < 0$ となる場合は、出力波形の先頭欠落を防ぐために以下の無音余白 $M$ を自動挿入します。

$$M=\max(0,-\min_i B_i)$$

※WORLD系レンダラーでは、GUIの「文頭の長さ」を手動設定することで上限を設け、先行発声に含まれる不要ノイズを切り落とすことが可能です。

## 5. 包絡線（エンベロープ）による波形接続

原音同士を単純に加算すると、重複部分の音量が過大になったり、境界でポップノイズが発生したりします。これを防ぐため、包絡線（エンベロープ）を用いて滑らかに接続します。

![5点包絡線による原音接続](assets/how-utautts-speaks-envelope.svg)

- **Classic UTAU（wavtool方式）:**
  各原音に5点エンベロープ（$p_0 \sim p_4$）を適用し、フェードイン/フェードアウトを行います。最終波形 $y(t)$ は各原音波形 $x_i$ と包絡線 $e_i$ の積の総和となります。
  $$y(t)=\sum_i e_i(t-B_i)\,x_i(t-B_i)$$

- **UtauTTS WORLD phrase（特徴量合成方式）:**
  波形を直接加算するのではなく、各原音から抽出したWORLD音響特徴量（ピッチ、スペクトル包絡、非周期性指標）をエンベロープ重みで補間・混合し、重み和で正規化した上で一括合成します。これにより、波形加算による音量膨張や位相干渉を防ぎます。

## 6. 音素長の制御（伸縮処理）

原音の録音長と指定されたモーラ長は異なるのが一般的です。しかし、全体を均等に伸縮させると子音の破裂感や過渡特性が損なわれ、発音が変化してしまう危険があります（例: 子音の過度な縮小による「す」→「つ」化）。

そのため、`consonant`（固定範囲）内の子音部は長さを極力維持し、後続の母音部を中心に伸縮を行います。

- **Classic UTAU:** 各レンダラー（resampler）が指定の長さ・ピッチへ個別に変換。
- **UtauTTS WORLD phrase:** 音響特徴の配置段階で子音と母音の時間配分を制御。大きく伸長する場合は母音部の過剰な伸びを制限します。さらに、自然音声モデルから予測された「子音から母音への遷移速度」に基づき、モーラ内の時間配分を最適化します（句末モーラなどを除く）。

## 7. 抑揚（ピッチ・音量）の予測

抑揚モデルは10ms単位のピッチ（音高）変化およびモーラごとの音量スケール（0.75〜1.3倍）を出力します。

![10ミリ秒単位の相対ピッチ曲線](assets/how-utautts-speaks-pitch.svg)

### 予測メカニズムと単位変換
音素文脈、モーラ内位置、単語境界、アクセント句情報、品詞などを入力とし、軽量なTCN（Temporal Convolutional Network）を用いて前後約5秒間の文脈を考慮したピッチ相対値（cent単位）を予測します。

centは周波数比を表す単位であり（100 cent ＝ 半音、1200 cent ＝ 1オクターブ）、モデルは絶対周波数（Hz）ではなく話者非依存の相対変化量を出力します。

原音固有の基本周波数を $F_{\mathrm{src},i}$、各種補正値を $q_i$、予測ピッチを $c(t)$ とすると、目標周波数 $F_{\mathrm{target},i}(t)$ は次のようになります。

$$F_{\mathrm{target},i}(t) = F_{\mathrm{src},i} \cdot q_i \cdot 2^{c(t)/1200}$$

これにより、ボイスバンク固有の声質やピッチ感を維持したまま自然な抑揚を付与できます。

### 補正と手動調整
抑揚の強さ設定（標準=4）に応じて曲線の振幅がスケーリングされ、疑問文の語尾上げなどの文末イントネーション補正も適用されます。また、`utautts-world-phrase` レンダラーでは無声破裂音直後の立ち上がりなど、自然発声特有の微細なピッチ変動（Micro-prosody）も補完されます。

GUIで抑揚を操作した場合は、手動修正されたcent値が自動予測曲線に加算または置換されます。

## 8. レンダラー（Renderer）による処理の違い

テキスト解析から抑揚予測までの処理は共通ですが、最終的な波形生成方式には以下の違いがあります。

| レンダラー | 処理内容 |
| --- | --- |
| **UtauTTS WORLD phrase** | 原音をWORLDで分析し、音響特徴量を配置・補間してフレーズ単位で一括再合成する |
| **Classic UTAU** | UTAU互換のresamplerで原音を個別に加工し、wavtool等で足し合わせて接続する |

※DiffSinger音源はこの連結フローを通さず、算出されたタイミングと抑揚情報を直接DiffSinger音響モデルへ渡して音声生成を行います（詳細は[DiffSinger](diffsinger.md)を参照）。

## 9. 英語の読み上げ

英語はUTAUの原音をつなぐ方式では聞き取れる発音になりませんでした。そこで英語では参照用の音声合成（Kokoro-82M）で文を読ませ、その音声に近いフレームを音源の録音から選んで、WORLDで合成し直します。

1. 英語の読みをKokoroの音素記号に直して読ませ、参照音声と内部のF0を得る
2. 参照音声と音源の録音から、20msごとの特徴量を求める
3. 参照の各フレームに近い音源のフレームを、前後のフレームも含めて選ぶ
4. 選んだフレームのWORLD音響特徴量を平均し、参照のF0で合成する

Whisper small.enで書き起こした単語誤り率は、テトの英語音源の10文で、従来の原音接続が67.2%、この方式が1.7%でした（Kokoroの音声は3.4%）。

### 参照音声の生成

参照にはKokoro-82M（声はaf_heart）を使い、英語の読み（ARPAbet、例: `HH AH0 L OW1`）をKokoroの音素記号に直して入力します。強勢の記号は母音の前に置き、語の区切りの`SP`は読点にします。疑問文は「?」、それ以外は「.」で終えます。

Kokoroは24kHzの音声、入力記号ごとの長さ（25ms単位）、内部で予測したF0（12.5msごと）を出力します。

### 特徴量

特徴量にはLibriSpeechの960時間で学習したHuBERT Base（`facebook/hubert-base-ls960`）の6層目を使います。音声を16kHzにして、20msごとに768次元の値を求めます。

### 音源の索引

照合の前に、音源フォルダ以下のすべてのWAVを解析して、音源ごとに索引を作ります。

| 内容 | 周期 | 解析 |
| --- | --- | --- |
| 特徴量 | 20ms | HuBERT Baseの6層目 |
| F0 | 5ms | Harvest（71〜1100Hz） |
| スペクトル包絡 | 5ms | CheapTrick。60次に符号化 |
| 非周期性指標 | 5ms | D4C（threshold 0.85）。3kHzごとの帯域に符号化 |

各ファイルで、包絡の符号の0次（音量）が95パーセンタイルより9（約45dB）以上小さいフレームは、無音として除きます。

索引は音源の読み込み時に作り、利用者ごとのキャッシュフォルダに保存します。音源フォルダのWAVの一覧、大きさ、更新時刻のどれかが変わると作り直します。テトの英語音源（558ファイル）では、WORLDの解析に8スレッドで約70秒かかります。

### フレームの照合

参照のフレーム $t$ と音源のフレーム $j$ の近さを、特徴量のコサイン類似度 $\cos(q_t,b_j)$ で測ります。有声か無声かが食い違う組には0.5を引きます。

$$s(t,j)=\cos(q_t,b_j)-0.5\,[\,v_t\ne v_j\,]$$

1フレームずつ最も近いものを選ぶと、20msごとに別の録音のフレームへ飛び、声が揺れて聞こえます。そこで、前後2フレームまでの近さを、同じ録音の中で続くフレームどうしで平均した値で選びます。

$$S(t,j)=\frac{\sum_{\delta=-2}^{2}w_\delta\,s(t+\delta,\,j+\delta)}{\sum_{\delta=-2}^{2}w_\delta},\qquad w_0=1,\quad w_{\pm1}=w_{\pm2}=0.5$$

$j+\delta$ が別の録音にまたがる項は、分子と分母の両方から除きます。$S(t,j)$ が高い順に4フレームを選びます。前後を含めると、録音の中で続くフレームが選ばれやすくなり、揺れが減ります。選ぶフレームを4つより減らすと、揺れが戻ります。

### 波形合成

選んだ4フレームについて、符号化したスペクトル包絡と非周期性指標を平均し、さらに時間方向に3フレームで平均します。平均でこもった音になるのを抑えるため、包絡の符号の2次以降の係数を1.4倍して強調し、全体の大きさは強調前に合わせます。

F0はKokoroのF0から作ります。有声区間のF0を対数で約20msの幅でなめらかにして、5msごとに直します。中央値が音高の指定（指定がなければ音源のF0の中央値）になるように、F0全体を平行移動します。

$$F_0(t)=F_{\mathrm{center}}\cdot\frac{F_{\mathrm{Kokoro}}(t)}{\operatorname{median}F_{\mathrm{Kokoro}}}$$

最後に、音源の標本化周波数と5msの周期で、WORLDで合成します。
