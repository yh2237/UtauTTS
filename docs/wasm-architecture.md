# Qt WebAssembly版の構成

Qt WebAssembly版の処理経路、状態管理、仮想ファイルシステムの構成をまとめた開発者向けの文書です。音声合成本体の構成は[UTAU音源の合成処理](synthesis-architecture.md)、全体の設計は[技術設計ガイド](technical-design.md)を参照してください。

## 処理経路と担当

```text
Main.qml（モバイル幅では MobileChrome.qml）
  -> Backend::callAsync（リクエストIDとコールバックを対応付け）
  -> engine-loader.js（メインスレッドの通信処理）
  -> engine-worker.js（呼び出しを直列に実行）
  -> Go Engine（ネイティブ版と共通）
  -> 処理結果、変更ファイル、削除パス
  -> メインスレッドのFSミラー
  -> C++コールバック -> QML
```

WorkerはGo、Open JTalk、WORLD、モデル、音源、生成ファイルを管理します。メインスレッドはQt、ファイル選択・ダウンロード、HTML Audioと、Qtが必要とするファイルのFSミラーを管理します。FSミラーはWorker側のファイルを参照するためのコピーで、エンジン用の独立したFSとしては扱いません。

生成WAV、付随ファイル、音源画像はQtまたはJavaScriptから同期的に読み出します。このため、処理結果のコールバックを呼ぶ前に、必要なファイルをFSミラーへ反映します。

音源の原音WAVはWorker内に保持します。リモート音源のmanifestからディレクトリ一覧とstat情報を取得し、WAV本体は最初の読み出し時に取得してキャッシュします。取得した原音WAVはメインスレッドへ転送しません。

Qtの`QFile`からGoのFSへはアクセスできません。プレビュー音声の存在確認と削除は、wasmではJavaScript経由で仮想FSを操作し、ネイティブ版では通常のファイル操作を使います。

`?async=0`は、メインスレッドでエンジンを動かす互換用の経路です。通常はWorker経路を使います。同期経路の初期化処理は別実装で、同梱リモート音源には対応していません。

## 状態管理とデータ形式

### 音素ごとの上書き

音素ごとの上書き値は、対象のunit番号を含む次の形式で保持します。

```json
[{"unit_index": 2, "pitch_factor": 1.7, "resampler_volume": 80}]
```

配列の位置ではなく、各要素の`unit_index`で対象を指定します。`UnitOverrides.js`の更新・削除処理をデスクトップとモバイルで共有し、エディタとGoへ同じ形式を渡します。

### 非同期処理の結果

解析・合成の結果は、ListModelの行番号ではなく発話IDと変更番号に対応付けます。発話を編集すると変更番号が変わり、並べ替えても発話IDは維持します。

モバイルでは、同じ発話ID・変更番号に対する解析要求を重複して送信しません。Backendがbusyで解析要求を受け付けない場合は、処理が空いた後に再試行します。

初回再生は解析の完了を待ってから合成します。古い変更番号や別の選択発話に対する合成結果では、再生を開始したり、選択中のエディタのunit列を置き換えたりしません。

### ファイルの変更管理

FSの変更番号はmount、write、truncateで更新します。同じバイト数の書き換えでも変更番号が変わります。FSミラーの同期はファイルサイズではなく変更番号を比較し、削除したパスも反映します。

`readFile`が返すバイト列はFS内部のデータへの参照です。同期対象の内容を書き換える場合は、返されたバイト列を直接変更せず、FSの書き込みAPIを使ってください。

### 回帰テスト

リポジトリ直下で次を実行します。

```sh
node --test web/test-wasm-regressions.cjs web/test-asset-paths.cjs
```

このテストは実装のFS、Worker通信・ミラー処理、共通の上書き処理、QMLから取り出した状態管理関数を検査します。QtのバインディングやCanvasは再現しません。同じテストをwasmのCIでも実行します。

FSシムを変更した場合は、`web/build.ps1`または`web/build.sh`を実行し、`web/dist/fs-shim.js`を更新します。Qtのビルドではホストスクリプトを自動的にコピーします。

Qt wasm版とネイティブ版の両方をビルドして確認します。ビルド済みのエンジン・辞書・音源がある場合は、`web/test-synthesize.cjs`で解析・合成の経路も確認します。
