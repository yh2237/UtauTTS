# Qt WebAssembly版の構成

ブラウザで動くQt WebAssembly版の構成、メインスレッドとWeb Workerの通信、仮想ファイルシステムの同期を説明します。

---

## 1. 処理フローとスレッド分担

```text
Main Thread (Qt / UI)               Web Worker (Go / DSP / Synthesis)
┌─────────────────────────┐         ┌─────────────────────────┐
│ Main.qml                │         │ Go Engine (Wasm)        │
│   ↓                     │         │   ↓                     │
│ Backend::callAsync      │──Post──>│ engine-worker.js        │
│   ↓                     │         │   ↓                     │
│ engine-loader.js        │<──Done──│ 音声合成 / 特徴量計算   │
│   ↓                     │         │   ↓                     │
│ FSミラー同期            │         │ 仮想FSへの書き込み      │
│   ↓                     │         └─────────────────────────┘
│ HTML5 Audio再生 / QML   │
└─────────────────────────┘
```

- メインスレッド: QMLの描画、UIの操作、HTML5 Audioでの再生と、Qtが読むファイルシステム（FS）のミラーを受け持ちます。
- Web Worker: Goの合成エンジン、Open JTalk、WORLD、音響モデル、音源のキャッシュ、波形の生成を受け持ちます。重い音声処理でUIの描画が止まらないように分けています。

---

## 2. リモート音源のオンデマンド読み込み

ボイスバンクは全体の容量が大きいので、起動時にすべてのWAVをダウンロードすることはしません。
1. 起動時は音源のマニフェストからファイルの一覧を取得します。`oto.ini`などの各ファイルは読むときに取得します。
2. 合成の前に、その文の原音候補のWAVだけを最大8並列で先に取得し、仮想FSに置きます。

---

## 3. 状態管理と非同期の整合性

- 発話IDと変更番号: 解析や合成の結果は、UIの行番号ではなく、発話ごとのIDと変更番号に結び付けて管理します。続けて編集しても、古い合成結果で最新のUIの状態を上書きすることはありません。
- ファイルの同期: Workerは呼び出しの前後でファイルの更新番号を比べ、Worker内で書き出したWAVなどのファイルをメインスレッドのFSミラーに写します。これでQtからファイルを同期的に読めます。
