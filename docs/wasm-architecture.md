# Qt WebAssembly版の構成

Webブラウザ上で動作するQt WebAssembly版の内部アーキテクチャ、メインスレッドとWeb Worker間の通信、および仮想ファイルシステムの同期設計について解説します。

---

## 1. 処理フローとスレッド分担

```text
Main Thread (Qt / UI)               Web Worker (Go / DSP / Synthesis)
┌─────────────────────────┐         ┌─────────────────────────┐
│ Main.qml                │         │ Go Engine (Wasm)        │
│   ↓                     │         │   ↓                     │
│ Backend::callAsync      │──Post──>│ engine-worker.js        │
│   ↓                     │         │   ↓                     │
│ engine-loader.js        │<──Done──│ 音声合成 / 特徴量計算   │
│   ↓                     │         │   ↓                     │
│ FSミラー同期            │         │ 仮想FSへの書き込み      │
│   ↓                     │         └─────────────────────────┘
│ HTML5 Audio再生 / QML   │
└─────────────────────────┘
```

- **メインスレッド**: Qt QML描画、UI操作、HTML5 Audio再生、およびQtが読み出すためのファイルシステム（FS）ミラーを管理します。
- **Web Worker**: Go合成エンジン本体、Open JTalk、WORLD、音響モデル、音源キャッシュ、および波形生成処理を管理します。高負荷な音声処理がUI描画をブロックしない構成となっています。

---

## 2. リモート音源のオンデマンド読み込み

Wasm環境ではボイスバンク全体の容量が大きいため、すべてのWAVを起動時にダウンロードすることはしません。
1. 音源マニフェストからファイル一覧と `oto.ini` を先行取得します。
2. 合成実行時、選択された原音候補のWAVのみを最大8並列でプリフェッチ（先行ダウンロード）してキャッシュします。

---

## 3. 状態管理と非同期整合性

- **発話IDと変更番号**: 解析や合成の結果は、UIの行番号ではなく「発話固有ID」と「変更バージョン番号」に紐付けて管理されます。ユーザーが連続編集した場合でも、古い合成結果が最新のUI状態を上書きすることはありません。
- **ファイル同期**: Worker内で生成されたWAVファイルは、更新番号（世代）を比較してメインスレッドのFSミラーへ同期され、Qtから同期的に読み出し可能になります。
